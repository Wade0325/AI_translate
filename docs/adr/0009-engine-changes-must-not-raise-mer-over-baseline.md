# 本機轉錄的改動以「錯字率不准比基準高」把關，基準在同一台電腦上跑出來

ADR 0002 要求日文與中文各有評測集，以「不准變差」把關；這份記錄怎麼判定（#15）。#84 實測，同一台電腦、同一套環境重跑本機轉錄，輸出逐位元組相同，所以錯字率只要有變，就是改動造成的，不需要容忍值來吸收雜訊。因此動到本機轉錄路徑的 PR 以語言為單位比較：同一種語言的所有片段合起來算，錯字率或 cpMER（連說話者標記一起算的錯字率）只要比基準高，就是回歸，代理不得自己合併；使用者明確接受、並在 PR 上記下理由之後才可以合併。基準是 main 在同一台電腦、同一套環境（顯卡、驅動、套件版本、模型權重的 revision、設定）上的評測結果，存在研究區；動到本機轉錄路徑的 PR 合併後，由它的結果接替。日文以字計，漢字、平假名、片假名每字 1 個 token，和中文一樣。

評測集只用授權明確的公開錄音，不用使用者自己的錄音，也不用合成語音（使用者 2026-10-19 的決定）：#121 推薦的中日文各 5 段，加上 JVS 的耳語。標準答案由代理拿底稿和兩個本機模型的轉錄逐句對照起草，使用者只聽三方不一致的地方並確認。

## 考慮過的選項

- **容忍 X 個百分點以內的變差**：比較少打擾使用者，但 X 沒有數據可依。目前唯一量到、確實由改動造成的變差（強制每 240 秒切段，+0.37～+0.40 個百分點）會被 0.5 的容忍值放過。
- **以成對比較的 95% CI 判斷**：在同一台電腦上，CI 反映的是換一批句子的抽樣誤差，不是重跑的雜訊。只擋整段 CI 都落在變差一側的改動，會放過小幅的回歸；看上界的話，幾乎每個改動都會被擋。
- **每個 PR 都重跑 main**：不必管理基準，但同一套環境重跑 main 一定得到同一份輸出，每個這類 PR 白花一倍的 GPU 時間。

## 後果

- 換了顯示卡、驅動或依賴版本，舊的基準就不能用，要在新環境重建；評測數字不能跨電腦比較。
- 只把關本機的預設模型（moss-align）；其他本機模型在 #20 決定去留時再決定。Gemini 的改動不附評測：程式沒有固定取樣，重跑可能不同，評測又要付費、要上傳音檔；照 `docs/agents/merging.md` 由使用者實測。
- RTF 與峰值顯存只列出、不擋合併：耗時隨電腦的負載變動，峰值顯存隨顯示卡變動。
- 有 4 段只能留在本機（AISHELL-4、立法院質詢、衆議院審議、JVS 耳語），完整的評測只有維護者的電腦跑得了。外部貢獻者的 PR 由維護者代跑；公開 repo 不用 self-hosted GPU runner 跑 fork 來的 PR。
- 立法院質詢與 JVS 耳語限非商業用途，專案商業化之前要停用，或先取得權利人的同意。
- 標準答案與片段清單在 v0.1 都留在研究區。要讓外部的人重現時，可以公開的 7 段再搬進 repo，並附署名與授權。
- 標準答案分批啟用：經使用者確認的片段先開始把關，評測摘要寫明用了哪幾段。
- 片段的說話者安排量不到說話者分離時，標準答案註明「cpMER 不計」，那一段只算錯字率、不進 cpMER 的判定（使用者 2026-10-31 的決定，#273）。例如 JVNV：四位說話者唸同一份台本、依序接成區塊，兩個本機模型都只分出男女兩位，cpMER 約 100%；修好漏轉的字反而讓 cpMER 變高，照樣把關會把變好判成回歸。標準答案照樣記下真正的說話者，不配合模型併成兩位。
